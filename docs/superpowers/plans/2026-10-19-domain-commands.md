# Native domain commands for Broker Flow

Execute inline under the approved consolidated design, component6. Keep production and every bot unchanged. Reuse the current fenced Flow effect ledger and CRM services; no second bot, arbitrary routes, SQL, model-selected Ruby or public send.

## Contract

Add a finite `domain` Flow node: create/reuse the current conversation lead, create a CRM task, or record a CRM meeting. Actor, company, inbox, contact and routing revision come from the authenticated central binding. Titles/due dates may use Flow variables, but the final typed payload is validated before admission. Owners come from the current native account directory and are revalidated before native execution.

Existing tag/attribute/note/resolve protocol2 endpoints and capabilities stay compatible. A separate authenticated `jrc-domain-commands/1` capability controls domain availability. Domain effects reuse the durable protocol2 causal proof and immutable ledger, with a typed domain result and event envelope (command ID, event kind, resource identity). A native meeting is a CRM record, not a phone call or external invitation.
