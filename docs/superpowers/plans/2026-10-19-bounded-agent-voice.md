# Bounded NICO tools, knowledge and operator voice acceptance

Continue inline under approved design components7–8, preserving the same Rails,
Sidekiq and NICO runtime families. No production activity or customer bot.

## Component7

Reuse OperatorSession's persisted workflow/commands, twelve-step cap, current
native tool policies, account usage/reservation ledger, and approved knowledge.
Prove the cap, uncertainty stopping continuation, knowledge tenant isolation and
revocation. Run existing budget, reservation, inference, runtime/citation and native
domain regressions. Do not create a second agent or bypass public-send review.

## Component8

Add an explicitly started operator conversation mode around existing recording,
account-provider transcription and browser speech. Default off, maximum five
minutes/twelve turns, per-turn transcript review, speech/silence end detection.
Pause recording while submitting or reading a reply; stop for approval/unknown
actions, calls, changed account/conversation, hidden page or panel closure.
Manual edit/cancel interrupts it. It may ask NICO internally; existing mutation
confirmation and Broker ownership checks remain authoritative.

This is microphone/audio for the operator. It neither registers a SIP/WhatsApp
session nor certifies inbound call, RTP/media, call transfer or Meta assets. Real
browser audio/provider quality and WhatsApp call transport need separate configured
homologation. Expose that difference clearly; no invented supported capability.
